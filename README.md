# Транскрибатор

Сервис для разбора записей разговоров. Кидаешь аудиофайл — получаешь текст с разбивкой по спикерам и краткий разбор: о чём говорили, что решили, кто что должен сделать, где риски.

Писал под свою задачу: разгребать записи созвонов и звонков, чтобы не переслушивать их вручную. Всё крутится локально, ни один байт аудио наружу не уходит — это было условием, поэтому никаких облачных API, только свои модели на своём железе.

## Как это работает

Файл проходит через четыре шага:

1. **Аудио.** Декодирую через ffmpeg, привожу к 16 кГц моно/стерео. Если запись стерео и это телефонный звонок (два почти независимых канала) — разбираю каналы по отдельности, так спикеры делятся сами собой.
2. **Распознавание.** Режу на куски по тишине (VAD) и прогоняю через Whisper. Движка два: `faster-whisper` и `whisper.cpp` — какой брать, решает конфиг (почему два — ниже).
3. **Спикеры.** Стерео-телефон — по каналам. Моно — по голосовому отпечатку (resemblyzer): считаю эмбеддинги кусков и группирую близкие.
4. **Разбор.** Собранный текст уходит в локальную LLM (Qwen2.5-7B через llama.cpp), она вытаскивает темы, решения, задачи и риски в структурированный JSON.

Результат кладётся в `OUTPUTS/` (JSON) и в SQLite — историю потом видно в веб-морде.

### Про очередь

Обработка не мгновенная — файл на 40 минут молотится минутами. Поэтому `/api/transcribe` не ждёт результат, а ставит задачу в очередь и сразу возвращает `job_id`. Дальше опрашиваешь статус или смотришь в UI. Внутри — один воркер, задачи идут по одной (две модели в память одновременно не влезут, гонять параллельно смысла нет). Незаконченные при рестарте задачи подхватываются заново — загрузки лежат не в `/tmp`, а в постоянной папке.

### Почему два движка Whisper

Деплой стоит на старой 1080 Ti (Pascal). Для LLM её хватает — llama.cpp собирается с CUDA и Qwen влезает в 11 ГБ. А вот `ctranslate2` (на нём faster-whisper) на Pascal с float16 еле шевелится, поэтому по умолчанию Whisper держу на CPU в int8. Если железо новее — переключаешь `device` и `compute_type` в конфиге, код сам подберёт остальное. `whisper.cpp` оставлен как GPU-вариант для случаев, когда CPU не тянет.

## Стек

Python 3.11, FastAPI + uvicorn. Whisper (faster-whisper / whisper.cpp), resemblyzer для спикеров, Qwen2.5-7B-Instruct в GGUF через llama.cpp для разбора. Всё пакуется в Docker поверх образа с CUDA.

## Запуск в Docker

Нужно: Docker, nvidia-container-toolkit и GPU где-то на 11 ГБ VRAM.

```bash
docker compose up --build
```

Первый запуск качает модели (~5–6 ГБ), это надолго — дальше они лежат в `./models` и переиспользуются. Когда поднимется, открывай `http://localhost:8000` — там веб-интерфейс: загрузка файла, список активных задач, история и логи.

Тома вынесены наружу, чтобы правки кода и конфига не требовали пересборки образа, а история и БД переживали перезапуск (см. `docker-compose.yml`).

## Запуск без Docker

Только если готов возиться со сборкой CUDA-колёс руками:

```bash
pip install -r requirements.txt
# llama-cpp-python обязательно с CUDA, иначе разбор уползёт на CPU и будет тормозить
CMAKE_ARGS="-DGGML_CUDA=on" pip install --force-reinstall --no-cache-dir llama-cpp-python
python run.py
```

## API

Форматы на вход: mp3, wav, m4a, ogg, flac, webm.

```bash
# поставить файл в очередь -> вернёт job_id
curl -F file=@запись.mp3 http://localhost:8000/api/transcribe

# статус задачи (когда done — внутри будет result)
curl http://localhost:8000/api/jobs/<job_id>

# что сейчас в работе
curl http://localhost:8000/api/jobs

# готовые разборы из OUTPUTS
curl http://localhost:8000/api/history

# здоровье: какие модели поднялись
curl http://localhost:8000/api/health
```

Готовый результат выглядит так:

```json
{
  "language": "ru",
  "text": "полный текст записи",
  "segments": [
    { "start": 0.0, "end": 3.5, "text": "Добрый день", "speaker": "SPEAKER_00" }
  ],
  "speakers": { "SPEAKER_00": "реплики первого", "SPEAKER_01": "реплики второго" },
  "summary": {
    "title": "Тема обсуждения",
    "summary": "О чём договорились в двух словах",
    "topics": [],
    "decisions": [],
    "action_items": [],
    "risks": []
  }
}
```

## Конфиг

Все настройки в одном `config.yml` в корне. Идея — описываешь железо, а программа сама раскидывает модели: сколько слоёв LLM класть на GPU, какой контекст, сколько потоков. Не устраивает авто-расчёт — прописываешь значение в `overrides`, оно перебьёт.

```yaml
hardware:
  device: "auto"      # auto / cuda / mps / cpu
  vram_gb: 11         # 0 если GPU нет
  ram_gb: 30
  cpu_threads: "auto"
```

Путь к конфигу можно переопределить переменной `CONFIG_PATH`.

## Структура

```
run.py                     — точка входа, поднимает uvicorn
config.yml                 — весь конфиг
Dockerfile, docker-compose.yml
transcriber/
  config/settings.py       — читает конфиг, раскидывает ресурсы по железу
  core/
    audio.py               — декодирование и обработка звука
    transcriber.py         — распознавание речи
    whisper_worker.py      — whisper.cpp в отдельном процессе
    diarizer.py            — определение спикеров
  services/
    summarizer.py          — разбор через LLM
    bootstrap.py           — докачка моделей при первом запуске
    jobstore.py            — очередь и история в SQLite
    storage.py             — запись результатов в OUTPUTS
  api/
    app.py                 — FastAPI, роуты, воркер очереди
    pipeline.py            — склейка всех шагов
    static/index.html      — веб-интерфейс
```
