# 🎙 Транскрибатор — CPU-сборка

Локальный сервис: загружаете аудиозапись разговора — получаете транскрибацию,
разметку спикеров и структурированный разбор (темы, решения, задачи, риски).
Всё считается **на CPU**, без видеокарты. Никуда ничего не отправляется.

---

## Требования к серверу

- **Docker** и **docker compose** (только это).
- Без GPU. Чем больше ядер CPU и RAM — тем быстрее.
- ~10 ГБ свободного места под образ и модели.

Проверить Docker: `docker --version` и `docker compose version`.

---

## Запуск одной командой

После распаковки архива:

```bash
cd transcriber
./start.sh
```

Или то же самое напрямую:

```bash
docker compose up --build
```

**Первый запуск** соберёт образ и скачает модели (~5–6 ГБ: распознавание речи +
модель пересказа) — это займёт время. Модели сохраняются в папку `models/` и при
следующих запусках не качаются заново.

Следить за стартом:

```bash
docker compose logs -f
```

Когда в логах появится `Application startup complete` — сервис готов.
Откройте в браузере:

```
http://<IP-сервера>:8000
```

Загрузите аудиофайл, дождитесь обработки, нажмите **«Скачать JSON»**.
Копия разбора также сохраняется на сервере в `OUTPUTS/` в папке вида
`разбор обсуждения <тема> от <дд.мм.гггг>/`.

Остановить: `docker compose down`

## CPU-режим (как задаётся)

Сборка уже настроена на CPU тремя способами (любой работает, по приоритету):

1. **Переменная окружения** `DEVICE=cpu` — задана в `docker-compose.yml`.
2. **Конфиг** `config/config.yml` → `hardware.device: "cpu"`.

GPU здесь не используется и не требуется.

---

## Использование всех ресурсов

- `hardware.cpu_threads: "auto"` в конфиге — сервис занимает **все ядра** CPU
  (и для распознавания, и для пересказа).
- Укажите реальный объём памяти сервера в `config/config.yml` →
  `hardware.ram_gb` (влияет на размер контекста модели пересказа).

---

## Скорость vs точность

Главная ручка — модель распознавания. Меняется без пересборки, через
переменную `WHISPER_MODEL` в `docker-compose.yml`:

| Модель | Точность | Скорость на CPU |
|--------|----------|-----------------|
| `large-v3` (по умолчанию) | максимум | медленно |
| `medium` | хорошо | заметно быстрее |
| `small` | средне | быстро |
| `tiny` / `base` | низко | очень быстро |

После смены значения: `docker compose up -d` (перезапустит с новой моделью).

> На CPU `large-v3` для длинной записи может считаться долго. Если важна
> скорость — начните с `medium`.

## API (без браузера)

```bash
# обработать файл
curl -F file=@запись.mp3 http://localhost:8000/api/transcribe > result.json

# проверить, что сервис жив и какие модели загружены
curl http://localhost:8000/api/health
```

Поддерживаемые форматы: `mp3`, `wav`, `m4a`, `ogg`, `flac`, `webm`.

## Структура

```
transcriber/
├── start.sh                 # запуск одной командой
├── docker-compose.yml       # настройки запуска (порт, модель, ресурсы)
├── Dockerfile               # CPU-образ
├── config/config.yml        # конфиг сервиса
├── models/                  # сюда качаются модели (создаётся при запуске)
├── OUTPUTS/                 # сюда сохраняются разборы
└── src/transcriber/         # код
```
